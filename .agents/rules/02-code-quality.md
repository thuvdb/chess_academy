# Code Quality Rule

- Ưu tiên code đơn giản, dễ review.
- Không refactor ngoài phạm vi task nếu không cần thiết.
- Không dùng `any` hoặc tắt type checking chỉ để làm hết lỗi.
- Error message phải hữu ích nhưng không làm lộ secret.
- Business logic quan trọng phải có test.
- Khi sửa bug, thêm regression test nếu phù hợp.
